what rich buys:Centralizing invariants inside Create means there is exactly one place a quote can become invalid — not one check per call site that someone has to remember to copy. And immutability is now a compile-time fact, not a convention: there is no Text setter to accidentally call, versus the anemic version where quote.Text = "whatever" compiled fine from literally anywhere.

Bug from anemic one: if six months from now someone adds an "fix a typo" admin endpoint. With the anemic Quote { get; set; }, the obvious implementation is quote.Text = req.NewText; await db.SaveChangesAsync(); — compiles, runs, ships. It silently violates "once created, Text can't be changed" because nothing in the type says otherwise; the rule only existed as a comment or a memory, not as code. With the rich version, that line doesn't compile — Text has no public setter — so the bug is caught by the compiler before it's ever a PR, let alone a production incident. That's the scenario I'd point to specifically, not "validation in general": it's the silent rule (immutability) that the anemic model had no way to defend, versus the loud rule (empty string rejected) that the anemic model's endpoint-level if checks already happened to catch, just less durably.
